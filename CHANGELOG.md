## [v4.0.0] - 2026-11-26
### Added
* **Client-Side Browser Vector Memory (`vectorStore.js`)**: IndexedDB-backed conversation memory (`livy-ui-vector-memory`) with zero-download BM25 keyword retrieval by default, Turn 1 positional anchor, and recent turn buffer.
* **Opt-In Lazy-Loaded Semantic Embeddings**: Optional Web Worker (`Xenova/all-MiniLM-L6-v2`, ~23 MB) controlled via `ai.semanticEmbeddings` (disabled by default) for unified 384-dim cosine similarity across Ollama, Google Gemini, and OpenAI.
* **Native Ollama Thinking Control**: Added `ai.ollamaThinking` (`disabled` | `enabled` | `auto`) using Ollama's native `/api/chat` endpoint (`think: false`) to suppress unwanted thinking tokens.
* **Query Feedback Alerts**: Added Web Audio API success/error chimes (`workbench.soundFeedback`), mobile/PWA vibration (`workbench.hapticFeedback`), and out-of-focus success toasts (`workbench.queryToasts`).
* **About & History in Settings**: Dedicated **About & History** section displaying author metadata and release timeline.

### Changed
* **First-Time Welcome Workspace**: New users start cleanly with the Welcome Screen in the editor and the left sidebar, right AI Copilot, and Result Table collapsed.
* **Real-Time Interactive Streaming Markdown**: Streaming responses render markdown live and allow clicking **Run Query** / **Copy** on rendered SQL blocks while streaming, without locking scroll when reading above.
* **Simplified Direct AI Tools**: Exposed flat catalog tools (`list_databases`, `list_tables`, `describe_table`, `list_sessions`) directly to the supervisor for small local models and removed automatic table injection from the base system prompt.

### Fixed
* Copilot welcome message on initial load and after clearing chat.
* Auto-reveal of the Result Table when running queries from the Editor, Sidebar, or AI Copilot.
* Removed trailing `?` appended to clicked chat suggestion chips.

## [v3.1.0] - 2026-11-18
### Added
* **Multi-Provider AI Copilot (`⌘⇧A` / `Ctrl+Shift+A`)**: Autonomous AI Copilot supporting local **Ollama** models (Gemma 2, Llama 3, Qwen 2.5, DeepSeek) with zero telemetry, **Google GenAI** (Gemini 2.5 Flash, Gemini 1.5 Pro, Flash-Lite), and **OpenAI** (GPT-4o, GPT-4o-mini, o1).
* **DeepAgents Multi-Subagent Architecture with Context Quarantine**: Supervisor agent delegating to isolated subagents (`schema_analyst`, `sql_specialist`, `cluster_operator`) that run private loops and return distilled summaries, achieving a 75%–85% token reduction per turn.
* **Interactive 1-Click SQL Action Cards**: Dedicated in-chat action buttons (`[▶ Run Query]`, `[+ Open in Tab]`, `[Insert]`, `[Copy]`) for every SQL block generated by the AI Copilot.
* **Single-Click Protection & Tab Deduplication**: Action Card `Open in Tab` disables itself on click with `<Check /> Opened in Tab` and automatically focuses existing tabs if the query is already open.
* **Local Workspaces via Native File System Access API**: Direct disk and Git repository access via `showDirectoryPicker`, project scaffolding templates, nested file tree explorer, and persistent IndexedDB directory handles.
* **Native Markdown Document Editing & Live Preview (`⌘⌥M`)**: Full Monaco Markdown editor with Mermaid diagram rendering, KaTeX LaTeX math support, and split-view preview.
* **Headless Query Execution on Welcome Screen**: Autonomous and Action Card queries execute and render live results in the Result Table even when no files are open in the editor.
* **Ollama Warm-Up Detector**: Non-blocking status banner indicating when local models take >3.5s to load weights into GPU VRAM.
* **Universal Markdown Code Block Copy**: Language-tagged copy buttons on every `<pre><code>` block and 1-click header message copy.

### Changed
* **Streamlined Compute & Session Manager**: Strict isolation between Apache Spark Livy endpoints and Apache Doris FE clusters, eliminating cross-engine pollution.
* **Unified Single-Card Architecture**: Active connection parameters integrated directly into the Endpoints section, eliminating duplicate host names, duplicate latencies, and redundant multiple `Attached` badges.
* **Smart Editor Tab Reuse**: AI write operations and query executions default to updating the active editor tab, preventing tab clutter.
* **Modern Two-Row Chat Input UI**: Redesigned auto-expanding card container (`min-h-[46px]`, up to 130px) eliminating text clipping and scrollbar collisions with the Send button.

### Fixed
* **`open_file` Workbench Tool**: Fixed bug where `open_file` failed to dismiss the Welcome Screen by ensuring files are added to `openFiles` state.
* **Autonomous Self-Healing on Runtime SQL Errors**: Corrected `handleRunSql` return contract so execution errors (e.g. `Unknown column`) trigger the AI agent's self-healing recovery loop instead of reporting false success.
* **Welcome Screen Result Tab Suppression**: Fixed Result Table and resize sash visibility when queries run without open editor files.

## [v3.0.0] - 2026-11-07
### Added
* **Dual-Engine Architecture (Apache Spark SQL ⇋ Apache Doris)**: Universal big-data SQL workbench supporting both Apache Spark SQL (via Livy REST sessions) and Apache Doris (via stateless FE HTTP Query API).
* **Compute & Session Manager (`Cpu` / `⌘⇧M`)**: Dedicated left sidebar panel featuring 1-click engine switcher pills (`⚡ Spark` / `🐬 Doris`), active connection health & latency ping, inline target database selector, and saved endpoints catalog.
* **Stateless Doris FE HTTP Query Execution**: Instant SQL query dispatch against Apache Doris frontends (`/api/query/<cluster>/<database>`) with zero session startup latency.
* **Doris Quick Cluster Tools**: 1-click cluster inspection shortcuts with inline `▶ Run` and click-to-insert for `SHOW PROC '/backends'`, `SHOW PROC '/frontends'`, `SHOW DATABASES`, `SHOW TABLES`, `SHOW RESOURCES`, `SHOW WORKLOAD GROUPS`, and `SHOW PROCESSLIST`.
* **Engine-Aware Autocomplete & Hover Docs**: Dynamic Monaco completion catalog that switches based on active compute—offering 112+ Doris functions, 32 Doris data types (`LARGEINT`, `BITMAP`, `JSONB`, `VARIANT`), 178 keywords, and 13 DDL snippets, while preserving Spark's 600+ functions when Spark is selected.
* **Native Doris AI & LLM Integration**: Pre-configured autocomplete and snippets for Ollama & OpenAI model resources (`CREATE RESOURCE "ollama_gemma2"`, `SET default_ai_resource`, `AI_TRANSLATE`, `AI_GENERATE`, `AI_SUMMARIZE`, `AI_MASK`).
* **Engine-Aware Static SQL Syntax Validation**: Intelligent parser switching (`MySQL` dialect for Doris, `SparkSQL` for Spark) with syntax masking for Doris-specific DDL and `SHOW` commands (`SHOW RESOURCES`, `SHOW PROC`, `DUPLICATE KEY`, etc.) to eliminate false-positive red squigglies while accurately catching real syntax errors.
* **Modernized Title Bar & Status Bar**: Header compute pill indicating engine, cluster, and status; status bar engine badge (`🐬 Doris · demo_db · Ready`) and latency diagnostics.
* **Universal SQL Scratchpads**: Scratchpad buffers (`Untitled-*`) automatically default to SQL syntax and execution mode.
* **Decoupled Backend Sidecar**: Spark container sidecar with built-in `livy-next` native CORS (`--cors-allowed-origins "*"`).

### Fixed
* Extensionless files and scratchpads misidentified as plain text preventing SQL execution.
* Validation false positives on Doris SHOW statements and custom resource properties.
* Ollama local AI resource connection endpoint routing for Docker containers.

[Details in Release Notes](release-notes/v3.0.0.md)

## [v2.0.0] - 2026-09-06
### Added
* **VS Code Settings Overlay**: Centered floating settings overlay (`⌘,` / `Ctrl+,`) with unboxed configuration rows, category sidebar navigation, modified indicators, and reset confirmation dialog.
* **Dual Settings Mode**: Live two-way synchronized graphical UI and Monaco JSON editor (`settings.json`).
* **Spark Conf Manager**: Visual key-value property editor with autocomplete datalist (`spark.sql.shuffle.partitions`, etc.) and 4 one-click presets (*Standard Local*, *Medium Performance*, *Delta Lake*, *Hive Warehouse*).
* **Session Lifecycle Manager**: Create compute sessions with custom memory/cores/JARs, attach/switch sessions, refresh state, and terminate sessions from the Settings UI.
* **Static Config Resilience**: Multi-pass configuration stripping for static Spark configs rejected by Livy with "Retry without custom configs" fallback.
* **Livy Host Manager**: Add, edit, test reachability (ping), and switch Livy servers with click-to-select host cards.
* **Authentic VS Code Dark Theme**: Color-matched editor palette (`#121314`), elevated active tab (`#2c2d2e`), and pink cylinder `Database` icon (`#ff7b72`).
* **Custom Monaco SQL Theme (`vscode-dark-custom`)**: Red-coral keywords (`#ff7b72`), golden yellow functions (`#dcdcaa`), ice-blue strings and backticks (`#a5d6ff`), and sky-blue identifiers/numbers (`#79c0ff`).
* **Spark SQL Backtick Support**: Extended Monaco SQL tokenizer to natively recognize backticked table and path identifiers.
* **Real-Time Static SQL Validation**: Instant SQL syntax parsing and inline error squigglies powered by `dt-sql-parser`.
* **Editor Minimap Preview**: Restored file preview minimap on the right margin with settings toggle.
* **Persistent 3-Dot Sash Grip**: Interactive vertical 3-dot sash resize handle between sidebar and editor that remains active even when the sidebar is collapsed.
* **Raw Livy Result Values & Inferred Types**: Preserved unformatted cell values from Spark Livy and integrated native Spark schema types into column headers and tooltips.
* **Eliminated Schema Explorer Storm**: Converted background pre-loader loops into strict on-demand loading with in-flight deduplication guards and query timeouts.
* **Decoupled Backend Architecture**: Decoupled Spark 4.1.2 sidecar with built-in `livy-next` native CORS and ultra-lightweight Caddy production web server.

### Fixed
* TitleBar Command Center pill centering to prevent horizontal shift on host switch.
* Removed legacy `(...)` menu button from the editor tab bar.
* Swallowed autocomplete popups occurring immediately after commas, spaces, and open parentheses.
* Infinite re-render loop between `LivyContext` host updates and `SettingsContext`.
