# Release Notes - v1.3.0

Release v1.3.0 - Docker Compose, Session Manager & Inline Execution 🐳
Run the entire Livy + Livy UI stack with a single docker compose up! Version 1.3.0 brings a fully containerized deployment pipeline, inline SQL execution from the gutter, a powerful session management dropdown, schema search, copy-to-clipboard across the app, toast notifications, and browser-level alerts for background queries.

✨ What's New
Inline SQL Execution: Click the ▶ play glyph in the editor's gutter margin to run individual SQL statements without selecting them. The editor parses your file into separate statements (split by ;) and places a run icon at the start of each one. Clicking it executes only that statement, with a yellow highlight on the running lines that clears on completion.
Docker Compose: Added docker-compose.yml that launches both the Apache Livy server (livy-server:8998) and Livy UI (livy-ui:4173) together. One command to spin up the full stack: docker compose up --build.
Multi-Stage Dockerfile with Git Fetch: The Dockerfile now has three stages — git-fetch (shallow-clones from GitHub via alpine/git), build (installs deps & compiles), and production (serves via vite preview). Build any branch on the fly with --build-arg GIT_BRANCH=<branch>.
Session Manager Dropdown: A new dropdown in the navbar lists all active sessions on the current Livy host. You can attach to any existing idle/busy session, create a new named session, or stop the current one — all without opening the connection modal.
Session Attach: Click any live session in the dropdown to instantly attach to it. The currently attached session is highlighted with an ATTACHED badge.
Session Delete (Stop): Stop and delete the current session directly from the session dropdown with a single click.
Toast Notifications: A new toast notification system (ToastProvider / useToast) shows non-blocking, auto-dismissing popups in the bottom-right corner for query completion, failure, and cancellation — with elapsed time badges. Stacks up to 3 toasts at once.
Browser Notifications: When the browser tab is not focused, completed/failed/cancelled queries trigger native OS-level Notification popups and update the page title with ✅/❌/⚠️ status indicators so you never miss a result.
Schema Search & Filter: The Schema Explorer now has a search bar that filters databases, tables, and columns in real-time. Matching nodes auto-expand, and all tables/columns are lazy-loaded on first search to enable deep filtering.
Drop Table from Schema Explorer: Each table node now has a trash icon (visible on hover) that lets you DROP TABLE directly from the sidebar, with a confirmation dialog. Underlying data for LOCATION-based tables is preserved.
Copy Buttons Everywhere:
Result Table — Copy full result as CSV (header + rows) with proper escaping.
Error Output — Copy the full error message.
EXPLAIN Plan — Copy the raw execution plan text.
Text Output — Copy plain text query results.
Schema Explorer — Copy qualified table names (`db`.`table`) or column names from the tree.
Named Sessions: You can now assign a custom name when creating a new session. The name appears in the navbar and session dropdown instead of just Session #id.

🔧 Technical Details
parseStatements() splits editor content by semicolons (stripping comments) and tracks startLine/endLine for each statement. Glyph decorations are placed via deltaDecorations at each statement's start line, and onMouseDown on GLYPH_MARGIN_TYPE triggers execution of the clicked statement. Running lines get a running-statement-line CSS class highlight that auto-clears on completion.
Dockerfile Stage 0 uses alpine/git with --single-branch --depth 1 for minimal, fast clones. Build args GIT_REPO and GIT_BRANCH are configurable at both docker build and docker-compose.yml level.
ToastProvider wraps the app via React Context; toasts auto-dismiss after 5 seconds with enter/exit CSS animations.
CopyButton component in ResultTable.jsx handles clipboard writes with navigator.clipboard and a document.execCommand("copy") fallback for older browsers.
Schema search triggers bulk lazy-loading of all tables and columns to enable deep filtering across the entire catalog tree.
fetchSessions / attachSession / deleteSession added to LivyContext reducer and exposed via useLivy().
Livy UI container uses depends_on: livy in Compose for correct startup ordering.
Version bumped to 1.3.0 in package.json.
